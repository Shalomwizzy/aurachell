# Aurachell — Developer README

Luxury home diffuser e-commerce store built on Laravel 10, Livewire 3, Alpine.js, and TailwindCSS.

---

## Requirements

| Tool | Minimum version |
|---|---|
| PHP | 8.1 |
| MySQL | 8.0 |
| Node.js | 18 |
| Composer | 2 |

PHP extensions required: `pdo_mysql`, `mbstring`, `openssl`, `tokenizer`, `xml`, `bcmath`, `fileinfo`, `gd`

## Local Development Setup

### 1. Clone and install dependencies

```bash
git clone <repo-url> aurachell
cd aurachell
composer install
npm install
```

### 2. Configure environment

```bash
cp .env.example .env
php artisan key:generate
```

Open `.env` and fill in at minimum:

```env
DB_DATABASE=aurachell
DB_USERNAME=your_db_user
DB_PASSWORD=your_db_password

ADMIN_EMAIL=admin@yourdomain.com
ADMIN_PASSWORD=YourSecurePassword@2026!

MAIL_HOST=sandbox.smtp.mailtrap.io
MAIL_USERNAME=your_mailtrap_user
MAIL_PASSWORD=your_mailtrap_pass
```

### 3. Create the database and run migrations

```bash
mysql -u root -p -e "CREATE DATABASE aurachell CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
php artisan migrate
```

### 4. Seed the database

```bash
php artisan db:seed
```

This creates:
- Super admin account using `ADMIN_EMAIL` / `ADMIN_PASSWORD` from `.env`
- All roles and permissions
- Default shipping zones (Lagos, South-West, South-South, North, Abuja, International)
- Default store settings (currency, return window, referral rewards, etc.)

### 5. Build frontend assets

```bash
npm run dev        # development with hot reload
npm run build      # production-ready build
```

### 6. Start the local server

```bash
php artisan serve
```

- Storefront: `http://localhost:8000`
- Admin panel: `http://localhost:8000/admin`

Login with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` you set in `.env`.

## Queue and Scheduler

Aurachell uses a **database queue** for all emails. Without a running queue worker, no emails will be sent.

**In development**, run these in separate terminals:

```bash
# Process queued jobs (emails, notifications)
php artisan queue:work --sleep=3 --tries=3

# Run scheduled tasks (cron)
php artisan schedule:work
```

## Scheduled Tasks

One cron entry handles everything. Laravel's scheduler dispatches each task at the right time.

| Command | Frequency | What it does |
|---|---|---|
| `paystack:reconcile` | Every 30 min | Finds orders stuck at `pending` for 1+ hour, verifies with Paystack API, marks paid/failed accordingly |
| `stock:clear-reservations` | Every 5 min | Releases expired stock holds from incomplete checkouts |
| `emails:cart-reminder` | Daily 10am | Cart abandonment emails to users with items left for 24h |
| `emails:wishlist-reminder` | Monday 9am | Reminds users their wishlist items are still available |
| `emails:new-month` | 1st of month 8am | New month email campaign with featured products |
| `backup:run --only-db` | Daily 2am | Database backup |
| `backup:clean` | Weekly | Removes old backup files |

### Manual campaign commands

```bash
# Notify all subscribers of a new product (run after publishing)
php artisan emails:new-product

# Festive campaigns
php artisan emails:festive --event=christmas
php artisan emails:festive --event=eid
php artisan emails:festive --event=easter
php artisan emails:festive --event=ramadan
php artisan emails:festive --event=new_year

# Test reconciliation without changing anything
php artisan paystack:reconcile --dry-run
```

## Order Status Flow

```
pending → paid → processing → packed → shipped → out_for_delivery → delivered
```

Also: `cancelled`, `refunded`

A customer email fires automatically on every status change. Admin order notification fires once when payment is confirmed.

## Paystack Integration

**Callback URL** (redirect after payment):
```
https://yourdomain.com/payment/callback
```

**Webhook URL** (server-to-server event — more reliable):
```
https://yourdomain.com/api/webhook/paystack
```

Register both in Paystack Dashboard → Settings → API Keys & Webhooks.

The webhook handles `charge.success` events. The reconciliation cron (`paystack:reconcile`) catches any payments that fell through the cracks when both fail.

## Deployment (Hostinger Shared Hosting)

### 1. Upload files

Upload everything **except** `node_modules/` and `vendor/`. Point the domain web root to the `public/` directory.

### 2. Install PHP dependencies on server

```bash
composer install --no-dev --optimize-autoloader
```

### 3. Configure environment

```bash
cp .env.example .env
# Fill in all production values, then:
php artisan key:generate
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

### 4. Migrate and seed

```bash
php artisan migrate --force
php artisan db:seed --force
```

### 5. Build assets locally, upload the result

Hostinger shared hosting cannot run npm. Build locally:

```bash
npm run build
```

Upload the generated `public/build/` folder to the server.

### 6. Set folder permissions

```bash
chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache
```

### 7. Add cron jobs (Hostinger → Advanced → Cron Jobs)

**Scheduler** (runs every minute, dispatches all scheduled tasks):
```
* * * * * cd /home/username/domains/yourdomain.com/public_html && php artisan schedule:run >> /dev/null 2>&1
```

**Queue worker** (Hostinger shared hosting doesn't support persistent daemons — this re-runs every 5 minutes and exits cleanly when empty):
```
*/5 * * * * cd /home/username/domains/yourdomain.com/public_html && php artisan queue:work --stop-when-empty >> /dev/null 2>&1
```

## Troubleshooting

**Emails not sending**
Run `php artisan queue:work` — without it, jobs queue up but never fire.
Check `storage/logs/laravel.log` for SMTP errors.

**"No application encryption key"**
Run `php artisan key:generate`.

**CSS/JS returning 404**
Run `npm run build` locally and upload `public/build/` to the server.

**Paystack callback not working**
Ensure `APP_URL` exactly matches the callback URL registered in Paystack.
Check that `PAYSTACK_SECRET_KEY` is correct.
Look for errors in `storage/logs/laravel.log`.

**Admin analytics dashboard shows no data**
`ANALYTICS_PROPERTY_ID` must be the numeric GA4 property ID — not the `G-` measurement ID.
GA Data API needs at least 48 hours of traffic data before it returns results.

**Reconciliation cron not running**
Test manually: `php artisan paystack:reconcile --dry-run`
Confirm the cron job is saved correctly in Hostinger → Cron Jobs.

**Backup command fails**
Set `MYSQL_DUMP_PATH` to the directory containing your `mysqldump` binary.
Hostinger/Linux: `/usr/bin` — DBngin Mac: `/Users/Shared/DBngin/mysql/8.0.33/bin`
